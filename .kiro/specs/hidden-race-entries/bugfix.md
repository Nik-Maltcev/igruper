# Документ требований к исправлению бага

## Введение

При записи на гонку в фазе `RACE_DAY` игроки видят, какие машины выбрали другие участники (имя игрока и название машины). Это нарушает правила игры (пункт 6 правил): выбор машины должен оставаться скрытым до момента старта гонки. Преждевременное раскрытие информации даёт тактическое преимущество — игрок может подстроить свой выбор под соперников.

Проблема локализована в компоненте `RaceCenter.tsx`, в подкомпоненте `EntryButton`, который отображает блок «Стартовая решётка» с именами игроков и их машинами ещё на этапе записи. Корректное поведение уже реализовано в `RaceResults.tsx` — стартовая решётка показывается только после начала гонки (фаза `RACING`, шаг `GRID`).

## Анализ бага

### Текущее поведение (Дефект)

1.1 КОГДА игрок записался на гонку в фазе `RACE_DAY` И другие игроки тоже записались, ТОГДА система отображает блок «Стартовая решётка» с именами других игроков и названиями их машин рядом с кнопкой записи

1.2 КОГДА игрок ещё не записался на гонку в фазе `RACE_DAY` И другие игроки уже записались, ТОГДА система отображает блок «Стартовая решётка» с именами других игроков и названиями их машин рядом с кнопкой «ЗАПИСАТЬСЯ»

1.3 КОГДА игрок просматривает список гонок в фазе `RACE_DAY`, ТОГДА система через функцию `getEntryLabel()` раскрывает полную информацию о заявках соперников (имя игрока + название машины) для каждой гонки

### Ожидаемое поведение (Корректное)

2.1 КОГДА игрок записался на гонку в фазе `RACE_DAY` И другие игроки тоже записались, ТОГДА система ДОЛЖНА отображать только количество записавшихся соперников (например, «Записано: 3») без раскрытия имён и машин

2.2 КОГДА игрок ещё не записался на гонку в фазе `RACE_DAY` И другие игроки уже записались, ТОГДА система ДОЛЖНА отображать только количество записавшихся соперников (например, «Записано: 3») без раскрытия имён и машин

2.3 КОГДА гонка переходит в фазу `RACING` (стартовая решётка в `RaceResults`), ТОГДА система ДОЛЖНА раскрывать полную информацию о всех участниках — имена игроков и их машины

### Неизменное поведение (Предотвращение регрессии)

3.1 КОГДА игрок записывается на гонку, ТОГДА система ДОЛЖНА ПРОДОЛЖАТЬ корректно сохранять заявку (player_id, car_id, race_id, day) в таблицу `race_entries`

3.2 КОГДА игрок отменяет заявку на гонку, ТОГДА система ДОЛЖНА ПРОДОЛЖАТЬ корректно удалять заявку из таблицы `race_entries`

3.3 КОГДА гонка начинается (фаза `RACING`, компонент `RaceResults`), ТОГДА система ДОЛЖНА ПРОДОЛЖАТЬ отображать стартовую решётку с полной информацией об участниках (имена и машины)

3.4 КОГДА игрок выбирает машину для записи на гонку, ТОГДА система ДОЛЖНА ПРОДОЛЖАТЬ проверять, что машина не заявлена на другую гонку в этот день

3.5 КОГДА игрок записан на гонку, ТОГДА система ДОЛЖНА ПРОДОЛЖАТЬ отображать его собственную заявку (название его машины и кнопку отмены)

---

### Условие бага (Bug Condition)

```pascal
FUNCTION isBugCondition(X)
  INPUT: X of type RaceViewState { phase: RoomPhase, otherEntries: RaceEntry[] }
  OUTPUT: boolean
  
  // Баг проявляется когда фаза — RACE_DAY и есть заявки других игроков
  RETURN X.phase = "RACE_DAY" AND length(X.otherEntries) > 0
END FUNCTION
```

### Спецификация свойства

```pascal
// Свойство: Проверка исправления — скрытие деталей заявок соперников
FOR ALL X WHERE isBugCondition(X) DO
  rendered ← EntryButton'(X)
  ASSERT NOT contains(rendered, otherPlayerName)
  ASSERT NOT contains(rendered, otherCarName)
  ASSERT contains(rendered, count(X.otherEntries))
END FOR
```

### Цель сохранения

```pascal
// Свойство: Проверка сохранения — поведение при гонке не изменилось
FOR ALL X WHERE NOT isBugCondition(X) DO
  ASSERT F(X) = F'(X)
END FOR
```

Это гарантирует, что для всех состояний вне фазы записи (включая фазу `RACING` с отображением стартовой решётки в `RaceResults`) поведение системы остаётся идентичным.
